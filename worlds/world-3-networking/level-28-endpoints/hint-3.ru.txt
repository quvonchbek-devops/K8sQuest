✅ Подсказка с решением:

Обоим подам нужен readinessProbe. ВАЖНО: пробу нельзя добавить работающему
поду — `spec.containers[].readinessProbe` неизменяемое поле (kubectl ответит
«may not be changed»). Поэтому поды ПЕРЕСОЗДАЮТСЯ.

1. Удалите старые поды:

    kubectl delete pod web-app-1 web-app-2 -n k8squest

2. Создайте их заново с пробой. Если вы нажали `Показать решение`, файл лежит
   в вашей сессии:

    kubectl apply -f solution.yaml -n k8squest

   Либо сохраните это в панели `Написать свой манифест` и примените сами
   (повторите для второго пода, поменяв имя и `-text`):

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: web-app-1
  namespace: k8squest
  labels:
    app: web
spec:
  containers:
  - name: app
    image: hashicorp/http-echo:latest
    args: ["-text=Pod 1 ready", "-listen=:8080"]
    ports:
    - containerPort: 8080
    readinessProbe:
      httpGet:
        path: /
        port: 8080
      initialDelaySeconds: 5
      periodSeconds: 5
      failureThreshold: 1
```

3. Дождитесь готовности подов (0/1 → 1/1):

    kubectl get pods -n k8squest -l app=web

4. Проверьте, что endpoints показывают ТОЛЬКО готовые поды:

    kubectl get endpoints web-service -n k8squest

Переход 0/1 → 1/1 происходит именно тогда, когда readiness probe прошла — и
только ПОСЛЕ этого под добавляется в endpoints.

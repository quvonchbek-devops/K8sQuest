🧭 Maslahat 2: SecurityContext ni Tushunish

SecurityContext pod/konteyner uchun xavfsizlik sozlamalarini belgilaydi:

```yaml
securityContext:
  runAsNonRoot: true             # root sifatida ishlashni taqiqlash
  runAsUser: 1000                # aniq foydalanuvchi ID
  allowPrivilegeEscalation: false # imtiyoz oshirishni taqiqlash
  capabilities:
    drop: ["ALL"]                # barcha Linux capability larni olib tashlash
  readOnlyRootFilesystem: true   # fayl tizimiga yozishni taqiqlash
```

Bu levelning MUAMMOSI: `runAsNonRoot: true` berilgan, lekin `runAsUser` YO'Q.
Kubernetes "root bo'lmasin" deydi, image esa (nginx) o'zini root bilan ishga
tushiradi — ziddiyat. Natijada konteyner umuman boshlanmaydi:
`CreateContainerConfigError`.

Ya'ni "runAsNonRoot: true" o'zi yetarli emas: QAYSI foydalanuvchi bo'lishini
ham aytish kerak.

Qo'yilgan cheklovlarni va konteyner nega boshlanmayotganini ko'ring:

    kubectl get pod web-app -n k8squest -o jsonpath='{.spec.containers[0].securityContext}'
    kubectl describe pod web-app -n k8squest

`describe` chiqishining `Events:` qismida sabab yoziladi:
`container has runAsNonRoot and image will run as root`.

Ikkinchi tuzoq: non-root foydalanuvchi 1024 dan kichik portga bog'lanolmaydi.
Shuning uchun yechim image ni ham almashtiradi —
`nginxinc/nginx-unprivileged` (8080-port).
